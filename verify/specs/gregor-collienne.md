## A10 验证结果（构建方）

- 被测文件：`r1-gregor.html`（2026-11-24）。工具：Playwright 1.63 无头 Chromium，`python3 -m http.server`，视口 1440×900（DPR 1）和 390×844（DPR 2、触摸）。测量脚本和原始结果在 scratchpad `build/gregor/verify.js`、`result.json`；并排对照图在 `verify/investigations/gregor-collienne/build/`。
- 「通过」只代表这一条写下来的标准成立。没有在真机（iOS / Android）上测过；手机结果全部来自 Chromium 的手机模拟。
- 动效时长有两种读法，表里都写：**声明值** = 运行中的过渡对象报告的延迟 / 时长（`getAnimations()`）；**逐帧值** = 每帧采样、从「看得出变了」到「看不出还在变」的时间（缓动曲线两头很平，所以逐帧值会比声明值短 0.1 秒左右）。规格写的「假时钟」没有用上（CSS 过渡不受假时钟控制），改用上面两种读法。
- 用户决定（覆盖第二部分里相冲突的写法）：两色照原作；手机也是 5 列、原尺寸；名字用 `PROFILE.nameEn`；只加一行小字「伊藤 あかり｜スタイリスト」；简介和联系方式放在菜单里；点照片 = 页内全屏单张视图。

## A10 再验证 2（用户反馈后）

- 日期：2026-11-24（第三轮）。被测文件：`r1-gregor.html`。只在无头 Chromium 里测（手机是模拟），没有真机。前面的声明和两节结果没有改动。
- 用户反馈：手机上的照片要更大；照片之间的留白不必等距，不规则地散开更有艺术感；现在尺寸偏小；稍微转一点角度。
- 对照图：`verify/investigations/gregor-collienne/build/fb2-*.jpg`（3 张）。

### 改了什么
1. **手机改成 3 列**（宽 ≤ 768px）：看上去是「左右两张 → 中间一张 → 左右两张…」。列距 33% VW，行距 73.5% VH；左右两列被屏幕边缘切掉一点（全身照约 17–22%）。中间列的第一格正好在屏幕中心，留空给名字。
2. **尺寸**：四类比例不变（0.72 / 0.88 / 1.0 / 1.22）。手机基准高 29% VH，桌面基准高从 32% VH 加到 35.8% VH（+12%），宽度上限桌面 21.2% VW、手机 56% VW。
3. **不规则散开**：骨架（列、行、错半格）不变，但照片不再放在格子正中。每格按格子编号算出一个固定的偏移（桌面最多约 ±69 / ±79px，手机 ±31 / ±61px），再做一轮「太近就推开」。每个周期另外空出几格（桌面 5 格，手机 4 格，都不在首屏）。偏移只由格子编号决定，所以循环回来位置相同、首屏加载后不会再动。
4. **轻微倾斜**：每张 ±1°–±3.5°，方向混合，约 12% 的格子保持 0°。脚本最上面有一个常数 `TILT_MAX_DEG`（带日文注释），改成 0 就全部变直。名字、加号、菜单、单张视图都不倾斜。
5. **名字**：桌面不变（40%）。手机改回一行（照片变大、改成 3 列后，中间格留空，一行不会压到照片）。
