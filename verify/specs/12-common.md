# 12番台（缝合版）共通の作り方 — 作る役（builder）向け

依頼主の言葉：「然后你缝合一下 做个9版左右 12打头」。調査済みの参照どうしを組み合わせた版を作る。

## 何を作るか
- スタイリスト 伊藤 あかり（Akari Ito）のポートフォリオの1ページ。HTML 1ファイル（CSS・JS は中に書く）。ファイル名は各版の指示どおり（例 `12a.html`）。
- データは既存のファイルを script タグでこの順に読む（中身は変えない）：`data/works.js`, `data/sizes.js`（window.SIZES: パス→[幅,高さ]）, `data/thumbs.js`（window.THUMBS: パス→小さい画像のパス。無いものは元の画像を使う）, `data/selection.js`（window.SELECTION: lead[], groups[{id,title,en,items[],gallery?[]}]）, `data/profile.js`（window.PROFILE）。
- ジャンルは「Selected」（SELECTION.lead）＋ SELECTION.groups の6つ。ジャンルの一覧に並べる画像は `gallery` があればそれ、無ければ `items`。

## 組み合わせる「部品」は規格から作る（原サイトのコードは見ない＝净室）
- 各版の指示にある規格（`verify/specs/<id>.md`）と調査記録（`verify/investigations/<id>.md`、同名フォルダの参考コマ）だけを読む。`scratchpad/refs/` の dom.json や CSS は開かない。
- すでにこのリポジトリにある自分たちのページ（`r1-gregor.html`, `r2-julia.html`, `r3-friends.html`, `r4-snog.html`）は自分たちのコードなので、読んで再利用してよい。規格の数値を満たす実装がそこにあるなら、そこから持ってくるのが早い。
- 組み合わせ方は各版の指示に従う。指示に無い細部は、規格と「依頼主の決めごと」に反しない範囲で自分で決め、最後の報告に書く。

## 全部の版に必ず入れるもの（依頼主＝スタイリスト本人の希望）
`r4-snog.html` に実装済み。同じふるまいにする（コードを持ってきてよい）。
1. ジャンルを選ぶと、そのジャンルの写真が横並びの一覧で出る：見出し「— Beauty —」、PC 3列・スマホ 2列、横長（見開き）は2列ぶん、写真は切らない、一覧は THUMBS の小さい画像。
2. 一覧の写真を押すと拡大：前へ／次へ（ボタン・←→キー・スマホはスワイプ）、×・写真の外・Esc・ブラウザの「戻る」で一覧へ。PC は写真を押すと元の大きさ。
3. 一覧の最後に、ほかのジャンルへのリンクと「お仕事のご相談・お問い合わせ」（mailto: PROFILE.email）。
4. `…#beauty` のようにジャンルを直接開ける。
5. 文字は淡く落ち着いた色。各版の指示にある2色（大きな文字用 tint／小さな文字と線用 ink）を使う。色を切り替える箱は付けない。

## 依頼主の決めごと
- 最初の画面で「伊藤 あかり｜スタイリスト」が読め、連絡先（お問い合わせ）へ1回の操作で行ける。
- ほとんどスマホで見られる。390×844 で、写真が小さすぎない・押せる大きさ（40px以上）・横にはみ出さない。PC の hover に頼る部品は、スマホではタップやスライドで同じことができるようにする。
- 写真は CSS で切らない・歪めない（規格が「原サイトは切る」としていて、各版の指示が明示的に許す場合だけ例外）。写真どうしが重なるのはかまわない。
- 雑誌名・ブランド名を文字として出さない（誌面の画像に写っているものはそのまま）。
- 作り物の宣伝文句を足さない。文章は PROFILE と SELECTION にあるものだけ。
- 原サイトの画像・ロゴ・コード・フォントファイルは使わない。フォントは `assets/fonts/` にあるもの（Anton, Archivo, Frank Ruhl Libre, Inter, Instrument Sans, Instrument Serif italic）か端末の書体。外部への通信なし、相対パスのみ。
- `prefers-reduced-motion` では動きを止める（機能は使える）。キーボードで操作できる。
- 始まりの演出は長くても 2.5 秒以内に操作できる状態にする。

## 検証（終わる前に必ず）
- `python3 -m http.server <各版の指示のポート>` を自分で立てて Playwright（導入済み。何もインストールしない）で 1440×900 と 390×844（deviceScaleFactor 2, hasTouch, isMobile）を確認。終わったら止める。
- 使った規格の「必須」項目のうち、この版に取り入れた部品に当たるものを測り、`verify/specs/<版のid>.md` を新しく作って表にする（項目・出どころの規格・測った値・基準・合格／不合格／測れない）。取り入れなかった部品の項目は書かない。
- 共通の5点（上の「必ず入れるもの」）と決めごとも同じ表に入れて確かめる。
- コンソールのエラー・読み込み失敗なし、横スクロールなし。
- 両方の大きさでスクリーンショットを撮って Read で自分の目で見る（最初の画面／操作中／一覧／拡大）。`verify/investigations/<版のid>/` に 4〜6 枚（横1600px以下、300KB以下の JPEG）。
- リポジトリで作る・変えるのは、その版の HTML、`verify/specs/<版のid>.md`、`verify/investigations/<版のid>/` だけ。git は実行しない。ほかの作る役が同時に別のファイルを作っている。
